# Neon Collector — Development Postmortem

## Goals

The goal was to turn a small one-mechanic arcade prototype into a complete start-to-finish browser game. The main loop is intentionally simple: collect cyan energy orbs, avoid red hazards, and reach 10 points before the 30-second timer expires.

## What was implemented

- A start screen, active play, pause/resume, win/loss feedback, and restart flow.
- Score, countdown timer, and locally persisted best score.
- Keyboard controls (WASD and arrow keys) plus on-screen touch controls.
- Optional generated sound effects, muted by default.
- Reduced-motion setting and visible keyboard focus.
- Responsive layout and original Canvas-rendered game objects.
- A concise controls, rules, and credits section.

## Challenges and trade-offs

The main design challenge was keeping the game readable while showing the timer, score, player, collectible, and moving hazards. The interface separates the HUD from the arena, uses distinct colors and symbols for collectibles and hazards, and keeps controls outside the play area.

The project intentionally avoids external image and audio files so the download remains small and licensing is straightforward. This gives the game a clean arcade style, although future versions could add original sprite art and more varied sound.

## Results

The release includes a self-contained HTML/CSS/JavaScript build and a repository-ready README. Automated JavaScript syntax validation is not a substitute for browser QA.

## Next steps

1. Ask at least three people to play and record their feedback.
2. Tune hazard speed and collision penalty based on observed difficulty.
3. Consider adding a high-contrast palette and a control remapping option.
4. If needed, replace the remote font import with locally hosted, properly licensed font files.
